# 인증 메일

Supabase가 보내는 인증 메일의 본문입니다. 대시보드에 붙여넣는 것이 적용이고,
여기 있는 파일은 **원본**입니다 — 대시보드 안에만 있으면 누가 언제 무엇을 바꿨는지
diff로 볼 수 없고, 프로젝트가 사라지면 복구할 방법도 없습니다.

| 파일 | 붙여넣을 곳 | 지금 쓰이나 |
| --- | --- | --- |
| `confirm-signup.html` | Authentication → Emails → **Confirm signup** | ✅ 회원가입 시 발송 |
| `reset-password.html` | Authentication → Emails → **Reset password** | ❌ 아직 앱에 재설정 화면이 없습니다 |

앱은 `signUp`과 `signInWithPassword`만 호출합니다. 그래서 실제로 나가는 메일은
가입 확인 하나뿐이고, **비밀번호를 잊은 고객은 현재 다시 들어올 방법이 없습니다.**
재설정 템플릿은 그 화면을 만들 때 함께 붙이려고 미리 넣어둔 것입니다.

## 왜 SMTP를 따로 붙여야 하나

Supabase 기본 메일 서버는 개발용입니다:

- **시간당 발송 한도가 한 자릿수**입니다. 가입이 몰리면 메일이 아예 나가지 않고,
  고객에게는 "가입은 됐는데 메일이 안 옴"으로 보입니다.
- 발신 도메인이 우리 것이 아니라 **SPF/DKIM 정렬이 되지 않습니다.** 네이버·다음은
  이 검사에 엄격해서 스팸함으로 가거나 아예 거부됩니다. 고객 대부분이 네이버를
  쓰는 상황에서는 치명적입니다.

`bio-lj.com` 도메인을 인증해 그 도메인으로 보내면 두 문제가 같이 해결됩니다.

## 설정 순서

1. **Resend에서 도메인 인증** — `bio-lj.com`을 추가하고, 표시되는 DNS 레코드를
   도메인 관리 화면에 등록합니다. 최소 SPF와 DKIM, 가능하면 DMARC까지.
   전파에 보통 몇 분에서 한 시간이 걸립니다.
2. **SMTP 자격증명 발급** — Resend에서 SMTP 사용자/비밀번호를 만듭니다.
3. **Supabase에 입력** — Authentication → Emails → **SMTP Settings**:
   - Host `smtp.resend.com`, Port `465`
   - Sender email 은 **인증한 도메인의 주소**여야 합니다. 여기가 어긋나면
     인증을 해놓고도 SPF가 깨집니다.
   - Sender name 은 고객이 받은편지함에서 보는 이름입니다.
4. **템플릿 붙여넣기** — 위 표대로.
5. **실제로 확인** — 네이버·다음·Gmail 각각으로 가입해보고, **스팸함까지** 봅니다.
   한 곳에서 잘 간다고 나머지가 되는 것이 아닙니다.

## 템플릿을 고칠 때

이메일 HTML은 웹 HTML이 아닙니다. 각 파일 맨 위 주석에 이유를 적어뒀지만 요약하면:
`<style>` 블록은 지워지고, flexbox와 grid는 Outlook에서 무너지고, 이미지가 많으면
스팸 점수가 올라갑니다. 그래서 전부 인라인 스타일에 `<table>` 레이아웃입니다.

한국어와 영어를 함께 넣은 것은 취향이 아닙니다. Supabase 템플릿은 프로젝트당
하나뿐이라 수신자 언어를 알 수 없고, 고객의 상당수가 한국 밖에 있습니다.
