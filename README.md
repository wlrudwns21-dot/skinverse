# Skinverse

AI 피부 분석 기반 K-뷰티 해외 직구 플랫폼. `project/`의 Claude Design 프로토타입
(`Skinverse.dc.html`, `Skinverse Admin.dc.html`)을 React로 구현한 것입니다.

- **고객용 스토어** (`/`) — 모바일 웹, 430px 고정폭
- **관리자 콘솔** (`/admin`) — 데스크톱, 최대 1280px

기본 언어는 **한국어**이며 헤더의 🌐 칩 또는 마이페이지 > 언어에서 English ·
中文 · ไทย로 전환됩니다.

## 실행

```bash
npm install
cp .env.example .env.local   # Supabase URL / 키 입력
npm run dev                  # http://localhost:5173  (관리자: /admin)
npm run build                # 타입 체크 + 프로덕션 빌드
npm run typecheck
```

React 19 + Vite + TypeScript + Supabase(인증 · DB).

## 회원 / 비회원

가입하지 않아도 둘러보고 체험할 수 있고, **저장되어야 의미가 있는 기능**부터 회원
전용입니다. 판정은 `src/auth/capabilities.ts` 한 곳에 모여 있습니다.

| 기능 | 비회원 | 회원 |
| --- | --- | --- |
| 홈 · 상품 목록 · 상세 | ✅ | ✅ |
| 날씨 루틴 보기 (도시 변경, AM/PM, 조언) | ✅ | ✅ |
| AI 피부분석 | 하루 1회 · 결과 미저장 | 무제한 · 기록 저장 |
| 장바구니 담기 | ✅ (가입 시 그대로 이어짐) | ✅ |
| 결제 · 구매 | ❌ | ✅ |
| 루틴 저장 | ❌ | ✅ |
| 미션 완료 · 포인트 적립 | 보기만 | ✅ |
| 리워드 교환 | ❌ | ✅ |
| 마이페이지 | ❌ | ✅ |

비회원의 1일 1회 체험은 브라우저에 날짜를 기록하는 방식입니다. 사이트 데이터를 지우면
초기화되는 **편의 장치이지 보안 장치가 아닙니다** — 체험은 가입을 유도하는 미끼이고,
이보다 강한 제한은 방문자 지문을 수집해야 해서 택하지 않았습니다.

## 관리자 콘솔 (`/admin`)

운영자 계정으로 로그인해야 열립니다. 관리자 명단은 이메일 기준이며, PostgREST가
노출하지 않는 `private` 스키마에 있습니다 — **명단 자체를 API로 읽을 수 없습니다.**

새 운영자를 추가하려면 Supabase SQL Editor에서:

```sql
insert into private.admin_emails (email, note) values ('someone@example.com', '메모');
```

해당 주소로 가입하는 순간 관리자가 됩니다. 가입 전에 미리 등록해도 됩니다.

화면의 로그인은 **무엇을 렌더링할지 정할 뿐이고, 실제 장벽은 RLS입니다.** 관리자가
아닌 계정이 UI를 우회해 직접 질의해도 자기 행 외에는 아무것도 읽지 못합니다.

| 화면 | 상태 |
| --- | --- |
| 대시보드 KPI · 국가별 매출 · 전환 퍼널 | 🟢 실제 데이터로 계산 |
| 주문 관리 (상태 변경 · 운송장 발번) | 🟢 DB에 저장 |
| 회원 관리 (포인트 지급) | 🟢 DB에 저장 |
| 상품 재고 · 미션 설정 · CS 문의 | 🟡 `src/data/` 샘플 — 새로고침 시 초기화 |

🟡 항목은 상품 카탈로그가 아직 파일 기반(`src/data/products.ts`)이기 때문입니다.
재고를 실제로 관리하려면 상품을 DB로 옮겨야 하고, 그러면 스토어도 DB를 보게 됩니다.
해당 화면에는 저장되지 않는다는 안내가 표시됩니다.

## 데이터가 저장되는 곳

| | 비회원 | 회원 |
| --- | --- | --- |
| 언어 · 도시 | localStorage | localStorage + `profiles` |
| 장바구니 | localStorage | `cart_items` (기기 간 동기화) |
| 포인트 · 스트릭 | 없음 | `profiles` |
| 분석 결과 | 메모리 (새로고침 시 소멸) | `scans` |
| 주문 | — | `orders` · `order_items` |
| 저장한 루틴 | — | `routines` |
| 미션 · 교환 | — | `mission_claims` · `redemptions` |

모든 테이블에 RLS(행 수준 보안)가 걸려 있어 **회원은 자기 행만 읽고 씁니다.** 브라우저에
노출되는 publishable 키만으로는 아무것도 할 수 없고, 권한 판정은 Postgres에서 이뤄집니다.
미션 중복 수령은 `(회원, 미션, 날짜)` 유니크 제약이 막습니다 — 더블클릭이나 요청 재전송으로
포인트를 두 번 받을 수 없습니다.

## 배포

Vercel에 저장소를 연결하면 Vite 프리셋이 자동 인식됩니다 (빌드 `npm run build`,
출력 `dist`). `vercel.json`의 rewrite 규칙이 모든 경로를 `index.html`로 보내므로
`/admin`에 직접 접속하거나 새로고침해도 404가 나지 않습니다 — 라우팅은 브라우저에서
react-router가 처리합니다.

**Vercel 환경변수** — Settings > Environment Variables에 아래 두 개를 넣어야 회원
기능이 동작합니다. 없으면 앱은 죽지 않고 비회원 전용 모드로 실행됩니다.

```
VITE_SUPABASE_URL
VITE_SUPABASE_PUBLISHABLE_KEY
```

**Supabase Site URL** — Authentication > URL Configuration의 Site URL을 배포 도메인으로
바꿔야 이메일 인증 링크가 localhost 대신 실제 사이트를 가리킵니다.

## 샘플 데이터 교체

실제 데이터로 한 번에 바꿀 수 있도록 **모든 더미 데이터는 `src/data/` 안에만**
있습니다. 화면 코드에는 데이터가 한 줄도 하드코딩되어 있지 않으므로, 아래 파일의
export만 교체하면 됩니다. 타입은 `src/data/types.ts`에 정의되어 있어 형태가 어긋나면
`npm run typecheck`에서 바로 잡힙니다.

| 파일 | 내용 |
| --- | --- |
| `products.ts` | 상품 카탈로그 (가격, 성분, 추천 사유, 그라디언트 썸네일) |
| `skin.ts` | AI 스캔 결과 3종 시나리오, 6개 진단 항목 정의 |
| `cities.ts` | 도시별 기온·습도·UV, 배송 가능 국가 |
| `rewards.ts` | 일일/주간 미션, 교환 리워드, 레벨 구간 |
| `commerce.ts` | 배송사·배송비·도착 예정일, 적립률/사용한도, 주문번호 접두사 |
| `account.ts` | 데모 회원 프로필, 시작 포인트, 스캔 이력, 기본 언어·도시 |
| `admin.ts` | 관리자 콘솔의 상품 재고·미션 설정·리워드 재고·CS 샘플 (주문·회원·KPI는 DB에서 옴) |

번역 문구는 `src/i18n/{en,ko,zh,th}.ts`에 있고 `Strings` 인터페이스가 4개 언어의
키를 강제합니다. 키를 추가하면 네 파일 모두 채워야 컴파일됩니다.

## 구조

```
src/
  StoreApp.tsx        고객용 셸 (헤더 + 화면 + 탭바 + 토스트 + PayPal 모달)
  AdminApp.tsx        관리자 셸 (사이드바 + 뷰 + 토스트)
  store/              고객용 상태 — 프로토타입 renderVals()를 옮긴 파생 로직
  admin/              관리자 상태와 6개 뷰
  screens/            홈 · 스캔 · 쇼핑 · 장바구니 · 결제 3단계 · 루틴 · 미션 · 마이페이지
  components/         헤더, 탭바, 토스트, PayPal 모달, 셀피 업로드 슬롯
  data/               샘플 데이터 (위 표)
  i18n/               4개 언어 문자열
  lib/css.ts          인라인 CSS 문자열 → React style 객체 변환
```

### 인라인 스타일에 대해

프로토타입은 모든 규칙을 `style="..."` 문자열로 표현합니다. 픽셀 단위로 동일하게
옮기기 위해 그 문자열을 그대로 유지하고, `s()` 헬퍼가 런타임에 React style 객체로
변환합니다 (문자열 단위로 캐시되어 블록당 1회만 파싱). 손으로 camelCase 객체로
바꿨다면 700여 개 블록에서 시각적 오차가 생길 수 있는 지점이었습니다.

## 프로토타입과 의도적으로 다른 부분

셋 다 원본의 시각적 의도를 살리기 위한 수정이며, 되돌리기 쉽습니다.

1. **토스트 중앙 정렬** — 원본은 `transform:translateX(-50%)`로 가운데 정렬하면서
   동시에 `animation:rise ... both`를 적용합니다. `rise`의 `to { transform: none }`이
   채움 모드 때문에 정렬을 덮어써서 토스트가 중앙선에서 오른쪽으로 밀려 잘립니다.
   정렬을 유지하는 `toastRise` 키프레임을 따로 두었습니다.
2. **헤더 한 줄 유지** — 430px 폭에 브랜드 + 4개 컨트롤은 영어 기준으로도 약
   17px 모자랍니다 (한국어는 약 29px). 언어 선택기를 🌐 칩 폭(46px)으로 줄이고
   포인트·가방 칩에 `white-space:nowrap`을 넣어 (원본이 마이페이지 버튼에만 적용해 둔
   것과 동일한 처리) 모든 칩이 한 줄로 유지되도록 했습니다. 언어 전체 이름은
   마이페이지 > 언어에서 그대로 볼 수 있습니다. 브랜드 태그라인
   `K-BEAUTY · AI SKIN LAB`은 폭이 부족하면 말줄임 처리됩니다.
3. **셀피 업로드 슬롯** — `project/image-slot.js`(1,225줄)는 디자인 캔버스 편집기용
   기능(리프레임 핸들, Unsplash 크레딧, 사이드카 저장, 캔버스 재인코딩)이 대부분입니다.
   제품 동작에 해당하는 부분만 `components/ImageSlot.tsx`로 옮겼습니다 — 빈 상태
   플레이스홀더, 클릭/드래그 업로드, 드롭 하이라이트, `clip-path` 마스크, cover 맞춤.

## 아직 데모인 것

회원 계정, 주문, 포인트는 실제로 DB에 저장됩니다. 아래는 아직 실물이 아닙니다.

- **AI 스캔** — 3.5초 애니메이션 후 `data/skin.ts`의 고정 결과를 보여줍니다. 실제
  이미지 분석은 하지 않습니다. 결과 저장·이력·1일 1회 제한은 실제로 동작합니다.
- **날씨** — `data/cities.ts`의 정적 값. 습도·UV 기반 루틴 분기 로직은 실제로 동작합니다.
- **PayPal** — 샌드박스 UI 모사. 1.5초 후 주문이 DB에 기록되지만 실제 결제는 없습니다.
- **관리자 콘솔의 상품·미션·CS** — 위 표의 🟡 항목. 주문과 회원은 실제 데이터입니다.

원본 핸드오프 안내는 `HANDOFF.md`, 디자인 원본은 `project/`, 대화 기록은 `chats/`에
그대로 두었습니다.
