# Skinverse

AI 피부 분석 기반 K-뷰티 해외 직구 플랫폼. `project/`의 Claude Design 프로토타입
(`Skinverse.dc.html`, `Skinverse Admin.dc.html`)을 React로 구현한 것입니다.

- **고객용 스토어** (`/`) — 모바일 웹, 430px 고정폭
- **관리자 콘솔** (`/admin`) — 데스크톱, 최대 1280px

기본 언어는 **한국어**이며 헤더의 🌐 칩 또는 마이페이지 > 언어에서 English ·
中文 · ไทย로 전환됩니다.

## 실행

```bash
npm install
cp .env.example .env.local   # Supabase URL / 키 입력
npm run dev                  # http://localhost:5173  (관리자: /admin)
npm run build                # 타입 체크 + 프로덕션 빌드
npm run typecheck
```

React 19 + Vite + TypeScript + Supabase(인증 · DB).

## 회원 / 비회원

가입하지 않아도 둘러보고 체험할 수 있고, **저장되어야 의미가 있는 기능**부터 회원
전용입니다. 판정은 `src/auth/capabilities.ts` 한 곳에 모여 있습니다.

| 기능 | 비회원 | 회원 |
| --- | --- | --- |
| 홈 · 상품 목록 · 상세 | ✅ | ✅ |
| 날씨 루틴 보기 (도시 변경, AM/PM, 조언) | ✅ | ✅ |
| AI 피부분석 | 하루 1회 · 결과 미저장 | 무제한 · 기록 저장 |
| 장바구니 담기 | ✅ (가입 시 그대로 이어짐) | ✅ |
| 결제 · 구매 | ❌ | ✅ |
| 루틴 저장 | ❌ | ✅ |
| 미션 완료 · 포인트 적립 | 보기만 | ✅ |
| 리워드 교환 | ❌ | ✅ |
| 마이페이지 | ❌ | ✅ |

비회원의 1일 1회 체험은 브라우저에 날짜를 기록하는 방식입니다. 사이트 데이터를 지우면
초기화되는 **편의 장치이지 보안 장치가 아닙니다** — 체험은 가입을 유도하는 미끼이고,
이보다 강한 제한은 방문자 지문을 수집해야 해서 택하지 않았습니다.

## 관리자 콘솔 (`/admin`)

운영자 계정으로 로그인해야 열립니다. 명단은 이메일 기준이라 **아직 가입하지 않은
주소도 미리 등록**할 수 있고, 그 주소로 가입하는 순간 권한이 붙습니다.

운영자 추가·삭제·역할 변경은 마스터가 **권한 관리** 화면에서 직접 합니다. SQL은
필요 없습니다. 명단(`public.admin_users`)은 RLS로 **마스터만 조회·수정**할 수 있어,
일반 관리자는 명단이 존재한다는 사실조차 API로 확인할 수 없습니다.

화면의 로그인은 **무엇을 렌더링할지 정할 뿐이고, 실제 장벽은 RLS입니다.** 관리자가
아닌 계정이 UI를 우회해 직접 질의해도 자기 행 외에는 아무것도 읽지 못합니다.

### 두 가지 권한

| | 마스터 | 일반 관리자 |
| --- | --- | --- |
| 대시보드 · 주문 · 상품 · 회원 · CS | ✅ | ✅ |
| 미션 · 포인트 설정 (적립률 · 사용한도) | ✅ | ❌ |
| 권한 관리 (운영자 추가 · 삭제 · 역할 변경) | ✅ | ❌ |

마스터 전용 메뉴는 일반 관리자에게 **보이지 않고**, 보인다 해도 RLS가 쓰기를 거부합니다.
마지막 남은 마스터는 삭제하거나 강등할 수 없습니다 — 아무도 콘솔에 들어올 수 없게 되는
상황을 DB 트리거가 막습니다.

### 화면별 저장 상태

| 화면 | 상태 |
| --- | --- |
| 대시보드 KPI · 국가별 매출 · 전환 퍼널 | 🟢 실제 데이터로 계산 |
| 주문 관리 (상태 변경 · 운송장 발번) | 🟢 `orders` |
| 회원 관리 (포인트 지급) | 🟢 `profiles` |
| 상품 재고 · 판매 상태 | 🟢 `products` — 스토어에 즉시 반영 |
| 미션 보상 · 리워드 재고 · 포인트 규칙 | 🟢 `missions` · `rewards` · `store_settings` |
| CS 문의 · 자동 응답 설정 | 🟢 `support_threads` · `support_messages` · `support_faqs` |

## 고객 문의 (챗봇 + 상담)

회원이 마이페이지 > 문의하기에서 질문하면, 질문에 FAQ 키워드가 **하나라도 포함되면
즉시 자동 답변**이 나가고 스레드는 `bot` 상태가 됩니다. 어느 키워드에도 걸리지 않은
질문만 `open` 상태로 어드민 대기열에 쌓입니다 — 운영자 책상에 올라오는 건 봇이 못 푼
것뿐입니다.

매칭은 임베딩이나 모델 호출 없이 **키워드 포함 개수로 최고점을 고르는 방식**입니다.
쇼핑몰 문의는 배송·포인트·환불·분석 네 갈래에 몰려 있어 이 정도로 충분하고, 즉답이
목적이라 지연이 없습니다. 못 맞힌 질문이 사람에게 가는 건 실패가 아니라 설계된 동작입니다.

운영자는 어드민 > CS 문의 > **자동 응답 설정**에서 키워드와 4개 언어 답변을 직접
수정할 수 있습니다. 배송·통관·포인트·환불·분석·결제 6개 항목이 4개 언어로 들어가 있습니다.

## AI 피부분석 연동

Perfect Corp 같은 유료 분석 API는 **키가 곧 돈**이라 브라우저에 둘 수 없습니다.
그래서 서버를 하나 두었습니다 — Supabase 엣지 함수 `analyze-skin`.

```
브라우저(사진) → analyze-skin(엣지 함수) → 벤더 API → 점수
                  └ 키 보관 · 호출자 식별 · 일일 쿼터 · 결과 저장
```

**사진은 저장하지 않습니다.** 분석에 쓰고 버립니다. 스토리지에도 로그에도 남기지
않습니다 — 얼굴 사진은 이 스토어가 배송하는 모든 국가에서 민감한 개인정보이고,
분석에 보관이 필요하지 않습니다.

**쿼터** — 호출마다 과금되므로 `analysis_usage` 테이블로 하루 호출 수를 셉니다.
회원은 user id, 비회원은 IP의 솔트 해시로 구분합니다(원본 IP는 저장하지 않습니다).
증가와 검사가 한 문장이라 동시 요청이 둘 다 통과하는 일이 없습니다. 기본값은
회원 20회 / 비회원 1회이며 함수 환경변수로 바꿉니다.

### 응답 매핑 (완료)

Perfect Corp은 ZIP을 돌려줍니다 — `skinanalysisResult/score_info.json` + 항목별 PNG
마스크. 우리는 JSON만 씁니다(마스크는 원본 사진에 검출 결과를 겹쳐 그리는 용도이고
이 제품은 그렇게 쓰지 않습니다). PNG는 압축조차 풀지 않습니다.

**점수 방향: 높을수록 좋음.** 문서에 "a higher score indicates healthier and more
aesthetically pleasing skin condition"이라고 명시돼 있어 우리 척도와 같습니다.
뒤집지 않습니다.

**`raw_score`를 씁니다, `ui_score`가 아니라.** 문서가 솔직하게 적어놨습니다 —
ui_score는 "소비자가 긍정적 평가를 선호하므로 상향 조정한" 값입니다. 이 점수는 화면
장식이 아니라 **가장 낮은 항목이 집중 케어 단계와 추천 제품을 결정**합니다. 듣기 좋은
숫자로 엉뚱한 세럼을 추천하는 것보다 정직한 48을 보여주는 편이 낫습니다.
`SCORE_SOURCE` 상수 하나로 바꿀 수 있습니다.

축 매핑 (HD 우선, 없으면 SD):

| 우리 축 | HD | SD |
| --- | --- | --- |
| 수분 | `hd_moisture` | `moisture` |
| 탄력 | `hd_firmness` | `firmness` |
| 모공 | `hd_pore.whole` | `pore` |
| 색소침착 | `hd_age_spot` | `age_spot` |
| 주름 | `hd_wrinkle.whole` | `wrinkle` |
| 민감도 | `hd_redness` | `redness` |

`hd_pore`·`hd_wrinkle`처럼 부위별로 나뉜 항목은 **`whole`(요약)을 읽습니다.** 샘플에서
`hd_pore.nose`는 29, `forehead`는 80으로, 아무 부위나 집으면 최저 항목 판정이 크게
왜곡됩니다.

피부 타입은 벤더의 `skin_type` 라벨을 우선 쓰고, 없으면 수분·유분 점수로 판정합니다
(유분은 **낮을수록 지성** — 높은 쪽이 건강한 끝입니다). `skin_age`도 함께 저장·표시합니다.

매핑은 **벤더가 공개한 샘플 응답 2종(HD·SD)으로 테스트**했습니다
(`src/analysis/perfectcorp.test.ts`, `npm test`). 인식 가능한 점수가 하나도 없으면
중립값 50을 지어내지 않고 예외를 던져, 호출자가 "샘플 결과" 배지가 붙은 데모로
떨어지게 합니다.

### 남은 작업 — 호출 순서만

`supabase/functions/analyze-skin/vendor.ts`의 `analyseWithPerfectCorp()` 하나입니다.
인증 → 파일 업로드 → 태스크 생성 → 폴링 → ZIP 다운로드까지가 남았고, ZIP을 받은
다음은 `readScoreZip()`이 이미 처리합니다. Developer Guide를 읽지 못해
**의도적으로 비워두었습니다** — 검증 안 된 규격에 맞춘 코드는 배포까지 통과하고
운영에서 실패합니다.

Supabase 대시보드 > Edge Functions > Secrets 에 `PERFECTCORP_API_KEY`,
`PERFECTCORP_API_SECRET`을 등록해야 동작합니다.

벤더가 설정되지 않은 동안에도 앱은 정상 동작하며, 샘플 결과에 배지를 달아 실제
측정이 아님을 명시합니다.

## 날씨별 루틴 기준

판정 기준은 전부 `src/routine/rules.ts` 한 곳에 있고, 각 임계값에 근거가 주석으로
달려 있습니다. 화면·문구 코드는 기준을 다시 계산하지 않고 이 결과만 받아 씁니다.

**자외선** — WHO/WMO 국제 자외선 지수(Global Solar UV Index) 공식 구간을 그대로 사용합니다.

| UV | 구간 | 적용 |
| --- | --- | --- |
| 0–2 | 낮음 | SPF50+ (광노화는 누적되므로 매일) |
| 3–5 | 보통 | SPF50+ 1회 |
| 6–7 | 높음 | 3시간마다 재도포 |
| 8–10 | 매우 높음 | 3시간마다 재도포 |
| 11+ | 위험 | 2시간마다 재도포 · 모자·선글라스 |

**습도** — 제형(가벼움/무거움)을 결정합니다. 45–65%가 실내 권장 구간이고, 그 아래는
경피수분손실이 늘어 밀폐가 필요하며, 위로는 유분이 겉돕니다.

| 습도 | 구간 | 아침 보습 |
| --- | --- | --- |
| <30% | 매우 건조 | 세라마이드 크림 + 오일 |
| 30–45% | 건조 | 세라마이드 크림 |
| 45–65% | 쾌적 | 수분 크림 |
| 65–80% | 높음 | 오일프리 젤 |
| ≥80% | 매우 높음 | 오일프리 젤 |

**기온** — 피지 분비량과 세안 강도를 결정합니다. (이전에는 화면에 표시만 되고 로직에
전혀 쓰이지 않았습니다.)

| 기온 | 구간 | 적용 |
| --- | --- | --- |
| <10° | 추움 | 무자극 크림 클렌저 · 저녁 단일 세안 |
| 10–18° | 선선 | 보습 강화 여지 |
| 18–25° | 온화 | 기본 |
| 25–30° | 따뜻 | 가벼운 제형 · 이중 세안 |
| ≥30° | 더움 | 가벼운 제형 · 이중 세안 |

**우선순위** — 습도가 제형을, 스캔 결과가 강도를 결정하며 **습도가 먼저**입니다.
수분 부족 피부라도 습도 78%에서는 젤을 씁니다. 포화된 공기에서 세라마이드 크림은
흡수되지 않고 겉돌기 때문입니다.

규칙은 순수 함수라 같은 입력이면 항상 같은 결과가 나오고, `src/routine/rules.test.ts`
16개 테스트가 구간 경계와 우선순위를 고정합니다 (`npm test`).

## 날씨 데이터

`src/weather/remote.ts`에서 **Open-Meteo**를 브라우저가 직접 호출합니다. API 키가
없어서 노출될 비밀이 없고 서버도 필요 없습니다. 기온·습도·UV 세 값만 받아 루틴 로직에
넣습니다. 10분 캐시하고, 실패하면 `src/data/cities.ts`의 고정값으로 떨어져 화면이
비지 않습니다.

> ⚠️ **라이선스**: Open-Meteo는 비상업적 용도에 한해 무료입니다(하루 약 1만 호출).
> 실제 판매를 시작하면 유료 플랜이나 상용 제공자로 바꿔야 하며, 고칠 곳은
> `src/weather/remote.ts` 한 파일입니다.

위치는 루틴 화면의 **📍 내 위치로 보기**를 누를 때만 요청합니다. 페이지 로드 시 묻지
않는 이유는, 이유 없이 뜬 권한 팝업이 영구 거부로 이어지기 쉽고 도시 선택만으로도
화면이 동작하기 때문입니다. 브라우저의 `timeout` 옵션이 콜백을 부르지 않는 경우가
있어 자체 감시 타이머(12초)를 두었습니다 — "위치 확인 중"에 영원히 멈추지 않습니다.
HTTPS에서만 동작하며 Vercel은 충족합니다.

## 데이터가 저장되는 곳

| | 비회원 | 회원 |
| --- | --- | --- |
| 언어 · 도시 | localStorage | localStorage + `profiles` |
| 장바구니 | localStorage | `cart_items` (기기 간 동기화) |
| 포인트 · 스트릭 | 없음 | `profiles` |
| 분석 결과 | 메모리 (새로고침 시 소멸) | `scans` |
| 주문 | — | `orders` · `order_items` |
| 저장한 루틴 | — | `routines` |
| 미션 · 교환 | — | `mission_claims` · `redemptions` |

카탈로그(`products` · `missions` · `rewards` · `store_settings`)는 누구나 읽을 수 있지만
**판매 중지된 행은 운영자에게만 보입니다** — 미출시 상품이 API로 새어나가지 않습니다.
쓰기는 운영자만, 포인트 규칙은 마스터만 가능합니다.

스토어는 시작할 때 `src/data/`의 값으로 즉시 렌더한 뒤 DB 행으로 교체합니다. DB가
닿지 않아도 빈 쇼핑몰 대신 조금 오래된 목록이 보입니다.

모든 테이블에 RLS(행 수준 보안)가 걸려 있어 **회원은 자기 행만 읽고 씁니다.** 브라우저에
노출되는 publishable 키만으로는 아무것도 할 수 없고, 권한 판정은 Postgres에서 이뤄집니다.
미션 중복 수령은 `(회원, 미션, 날짜)` 유니크 제약이 막습니다 — 더블클릭이나 요청 재전송으로
포인트를 두 번 받을 수 없습니다.

## 배포

Vercel에 저장소를 연결하면 Vite 프리셋이 자동 인식됩니다 (빌드 `npm run build`,
출력 `dist`). `vercel.json`의 rewrite 규칙이 모든 경로를 `index.html`로 보내므로
`/admin`에 직접 접속하거나 새로고침해도 404가 나지 않습니다 — 라우팅은 브라우저에서
react-router가 처리합니다.

**환경변수는 필수가 아닙니다.** Supabase 프로젝트 URL과 publishable 키는
`src/lib/supabase.ts`에 기본값으로 들어 있습니다. 둘 다 비밀이 아니고 — 키는 애초에
번들에 실리도록 설계됐으며 실제 보호는 RLS가 합니다 — 배포된 JS에서 누구나 읽을 수
있는 값이라, 환경변수로 숨겨도 얻는 보안이 없고 설정을 빠뜨리면 앱만 멈춥니다.

별도 스테이징 프로젝트를 쓸 때만 `VITE_SUPABASE_URL` · `VITE_SUPABASE_PUBLISHABLE_KEY`를
넣으면 기본값을 덮어씁니다.

> RLS를 우회하는 `service_role` 키는 절대 프론트엔드에 넣으면 안 됩니다. 서버 전용입니다.

**Supabase Site URL** — Authentication > URL Configuration의 Site URL을 배포 도메인으로
바꿔야 이메일 인증 링크가 localhost 대신 실제 사이트를 가리킵니다.

## 보안 헤더

`vercel.json`이 모든 응답에 헤더를 붙입니다. JSON에는 주석을 달 수 없어 이유를
여기 적어 둡니다.

| 헤더 | 하는 일 |
| --- | --- |
| `Content-Security-Policy` | 스크립트는 `'self'`만. `unsafe-inline`도 `unsafe-eval`도 없습니다 |
| `frame-ancestors 'none'` + `X-Frame-Options` | 클릭재킹 — 우리 화면을 남의 페이지에 투명하게 겹쳐 놓는 공격 |
| `Strict-Transport-Security` | 1년간 HTTPS 강제. `preload`는 뺐습니다 — 되돌리기 어려운 약속이라 직접 결정하실 일입니다 |
| `Permissions-Policy` | 카메라·위치는 `self`(스캔과 날씨에 필요), 마이크·USB 등은 완전 차단 |
| `Referrer-Policy` | 외부로 나갈 때 전체 경로 대신 출처만 보냄 |

CSP에서 느슨한 곳은 두 군데뿐이고, 둘 다 의도한 것입니다:

- `style-src`에 `'unsafe-inline'` — Google Fonts 스타일시트 때문입니다. CSS 주입은
  스크립트 주입과 위험도가 다르고, 정작 중요한 `script-src`는 조여 두었습니다.
- `img-src https:` — Perfect Corp이 돌려주는 마스크 이미지가 서명된 CDN URL이고
  그 호스트가 고정돼 있지 않습니다. 이미지는 실행되지 않습니다.

빌드를 이 헤더 그대로 서빙하면서 홈·`/admin` 두 화면을 띄워 CSP 위반 0건,
Marcellus 폰트 로드까지 확인했습니다.

## 손으로 켜야 하는 것

코드나 마이그레이션으로 처리할 수 없고 **대시보드에서 직접** 해야 하는 항목입니다.

1. **Authentication > Policies > Password**
   - *Leaked password protection* 켜기 — HaveIBeenPwned 대조. 지금은 꺼져 있어
     `password123` 같은 유출된 비밀번호로도 가입이 됩니다.
   - 최소 길이를 **8**로. 기본값 6이라 화면(8자)과 서버가 어긋나 있습니다.

2. **Edge Functions > analyze-skin > Secrets**
   - `ALLOWED_ORIGINS`에 실제 배포 도메인을 넣어주세요 (쉼표로 여러 개 가능).
     비워 두면 `*.vercel.app`과 localhost까지 허용하는 폭넓은 기본값으로 동작합니다.

## 샘플 데이터 교체

실제 데이터로 한 번에 바꿀 수 있도록 **모든 더미 데이터는 `src/data/` 안에만**
있습니다. 화면 코드에는 데이터가 한 줄도 하드코딩되어 있지 않으므로, 아래 파일의
export만 교체하면 됩니다. 타입은 `src/data/types.ts`에 정의되어 있어 형태가 어긋나면
`npm run typecheck`에서 바로 잡힙니다.

| 파일 | 내용 |
| --- | --- |
| `products.ts` | 상품 카탈로그 **초기값 · 폴백** (실제 운영 데이터는 DB `products` 테이블) |
| `skin.ts` | AI 스캔 결과 3종 시나리오, 6개 진단 항목 정의 |
| `cities.ts` | 도시 좌표 + 날씨 폴백값, 배송 가능 국가 |
| `rewards.ts` | 미션·리워드 **초기값 · 폴백** (실제는 DB), 레벨 구간 |
| `commerce.ts` | 배송사·배송비·도착 예정일, 적립률/사용한도, 주문번호 접두사 |
| `account.ts` | 데모 회원 프로필, 시작 포인트, 스캔 이력, 기본 언어·도시 |
| `admin.ts` | 주문 상태 라벨·색상 |

번역 문구는 `src/i18n/{en,ko,zh,th}.ts`에 있고 `Strings` 인터페이스가 4개 언어의
키를 강제합니다. 키를 추가하면 네 파일 모두 채워야 컴파일됩니다.

### 인라인 스타일에 대해

프로토타입은 모든 규칙을 `style="..."` 문자열로 표현합니다. 픽셀 단위로 동일하게
옮기기 위해 그 문자열을 그대로 유지하고, `s()` 헬퍼가 런타임에 React style 객체로
변환합니다 (문자열 단위로 캐시되어 블록당 1회만 파싱). 손으로 camelCase 객체로
바꿨다면 700여 개 블록에서 시각적 오차가 생길 수 있는 지점이었습니다.

## 프로토타입과 의도적으로 다른 부분

셋 다 원본의 시각적 의도를 살리기 위한 수정이며, 되돌리기 쉽습니다.

1. **토스트 중앙 정렬** — 원본은 `transform:translateX(-50%)`로 가운데 정렬하면서
   동시에 `animation:rise ... both`를 적용합니다. `rise`의 `to { transform: none }`이
   채움 모드 때문에 정렬을 덮어써서 토스트가 중앙선에서 오른쪽으로 밀려 잘립니다.
   정렬을 유지하는 `toastRise` 키프레임을 따로 두었습니다.
2. **헤더 한 줄 유지** — 430px 폭에 브랜드 + 4개 컨트롤은 영어 기준으로도 약
   17px 모자랍니다 (한국어는 약 29px). 언어 선택기를 🌐 칩 폭(46px)으로 줄이고
   포인트·가방 칩에 `white-space:nowrap`을 넣어 (원본이 마이페이지 버튼에만 적용해 둔
   것과 동일한 처리) 모든 칩이 한 줄로 유지되도록 했습니다. 언어 전체 이름은
   마이페이지 > 언어에서 그대로 볼 수 있습니다. 브랜드 태그라인
   `K-BEAUTY · AI SKIN LAB`은 폭이 부족하면 말줄임 처리됩니다.
3. **셀피 업로드 슬롯** — `project/image-slot.js`(1,225줄)는 디자인 캔버스 편집기용
   기능(리프레임 핸들, Unsplash 크레딧, 사이드카 저장, 캔버스 재인코딩)이 대부분입니다.
   제품 동작에 해당하는 부분만 `components/ImageSlot.tsx`로 옮겼습니다 — 빈 상태
   플레이스홀더, 클릭/드래그 업로드, 드롭 하이라이트, `clip-path` 마스크, cover 맞춤.
